# 02. 调度器与上下文切换

## 1. 调度规则

FreeRTOS 默认选择“最高优先级的就绪任务”运行。同优先级任务在启用时间片时，可在 Tick 中断到来后轮转；主动阻塞也会让出 CPU。

优先级高不表示任务永远占用 CPU。高优先级任务应在完成紧急工作后尽快阻塞，否则低优先级任务会饥饿。

## 2. Cortex-M 上的典型分工

| 异常 | 作用 |
| --- | --- |
| SVC | 启动首个任务等特权服务 |
| SysTick | 提供系统节拍并更新延时任务 |
| PendSV | 在低异常优先级下完成上下文切换 |

典型切换过程：

1. 中断或 API 使更高优先级任务就绪。
2. 内核挂起 PendSV。
3. 硬件自动保存部分寄存器，端口层保存其余寄存器。
4. 当前 PSP 写回 TCB 的栈顶指针。
5. 调度器选择下一个任务。
6. 从新任务栈恢复上下文并异常返回。

## 3. MSP 与 PSP

- MSP：复位后默认使用，通常供异常和中断使用。
- PSP：调度器启动后通常供任务线程使用。

这种分离使各任务拥有独立栈，而中断共享主栈。实际行为以所用 FreeRTOS 端口实现为准。

## 4. 优先级设计

建议先按“响应截止时间”和“阻塞依赖”分组，而不是按代码重要程度排序：

1. 硬实时、短执行的处理任务。
2. 数据搬运和协议接收任务。
3. 状态机、业务控制任务。
4. 日志、统计和后台维护任务。

避免把所有任务都设成高优先级。优先级层级越多，系统行为越难分析。

## 5. 常见问题

- 高优先级任务死循环：低优先级任务永远无法运行。
- 在临界区执行耗时操作：中断延迟不可控。
- 高优先级任务等待低优先级任务持有的资源：可能发生优先级反转。
- 误把数值大小当成中断逻辑优先级：Cortex-M 的 NVIC 编码需结合芯片位宽理解。
