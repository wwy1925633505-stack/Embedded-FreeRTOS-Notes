# 05. 内存管理与栈分析

## 1. FreeRTOS Heap 方案

| 实现 | 特点 | 适用思路 |
| --- | --- | --- |
| heap_1 | 只分配不释放 | 对象只在启动阶段创建 |
| heap_2 | 可释放，不合并相邻空闲块 | 新项目通常不优先选择 |
| heap_3 | 包装标准库 malloc/free | 依赖 C 库线程安全与锁实现 |
| heap_4 | 可释放并合并空闲块 | 常用的单内存区方案 |
| heap_5 | 支持多个不连续内存区 | RAM 分区复杂的 MCU |

实时系统需要关注的不只是“还剩多少内存”，还包括碎片、分配耗时以及失败后的恢复策略。

## 2. 栈中保存什么

任务栈通常包含：

- 局部变量和函数调用现场。
- 编译器生成的临时数据。
- 上下文切换保存的寄存器。
- 中断嵌套相关现场（取决于端口和栈模型）。

大型局部数组、深层调用、递归和格式化打印都会显著增加栈使用。

## 3. 栈检测

- 周期读取 `uxTaskGetStackHighWaterMark()`。
- 开启 `configCHECK_FOR_STACK_OVERFLOW` 并实现钩子。
- 在压力场景下测量，而不是只测空闲状态。
- 保留安全余量，并结合编译器栈分析或调用图复核。

高水位线反映历史最小剩余栈空间，不等于当前剩余空间。

## 4. 静态与动态创建

安全关键或长期运行系统常倾向静态创建任务、队列和信号量，以便：

- 启动时确定内存是否足够。
- 避免运行期碎片和不可预测失败。
- 更容易审查对象生命周期。

动态分配并非绝对不能使用，但必须检查返回值并定义失败策略。

## 5. 内存故障排查

1. 打开栈溢出和 malloc 失败钩子。
2. 记录各任务高水位线和堆最小剩余量。
3. 检查数组边界、悬空指针、并发访问和 DMA 缓冲区生命周期。
4. 在 HardFault 中保存关键寄存器、故障状态寄存器和栈帧。
5. 用 map 文件确认静态区、堆和栈的布局。
