# 09. 调试方法与 Git 工作流

## 1. 分层排查

面对“偶发丢包、卡死、数据错误”，先建立证据链：

1. **现象层**：触发条件、频率、版本、复现步骤。
2. **物理层**：电源、时钟、总线波形和信号完整性。
3. **驱动层**：状态寄存器、中断次数、DMA 错误和 FIFO 溢出。
4. **RTOS 层**：任务状态、优先级、栈水位、队列峰值和锁等待。
5. **协议层**：帧序号、长度、CRC、超时与重同步。
6. **应用层**：状态机转移、错误恢复和边界条件。

## 2. 工具与证据

| 工具 | 适合观察 |
| --- | --- |
| 万用表 | 静态电压、通断、电阻 |
| 示波器 | 电源纹波、模拟波形、时序质量 |
| 逻辑分析仪 | 数字总线解码、相对时序、帧内容 |
| J-Link/GDB | 断点、寄存器、内存、调用栈 |
| 串口日志 | 长时间状态、错误计数、事件顺序 |
| CAN 分析仪 | 总线帧、错误帧、负载与发送端确认 |

## 3. 日志设计

- 日志包含时间、模块、级别、事件码和关键参数。
- ISR 不直接输出长日志，可记录紧凑事件到固定缓冲区。
- 为高频错误使用计数器或限速，防止日志本身改变实时行为。
- 发布版本保留必要的故障快照和版本标识。

## 4. Git 分支

```text
main           可构建、可测试的稳定状态
feature/*      单一功能或单一知识主题
fix/*          缺陷修复
docs/*         纯文档更新
```

## 5. 提交信息

推荐 Conventional Commits 的简化形式：

```text
feat: add lock-free byte ring buffer
fix: reject oversized protocol payload
docs: explain ISR priority restrictions
test: cover CRC mismatch recovery
```

一次提交只解决一个问题，并说明“为什么修改”。提交前完成：格式检查、编译、测试和敏感信息检查。

## 6. 故障复盘模板

```text
Problem:      实际现象与影响
Trigger:      复现条件
Evidence:     波形、寄存器、日志、计数器
Root cause:   根因及其发生机制
Fix:          修改内容
Verification: 正常、边界、压力与回归结果
Prevention:   监控、测试或设计规则
```
