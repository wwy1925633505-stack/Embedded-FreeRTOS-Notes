# 01. FreeRTOS 任务模型

## 1. 任务是什么

任务是一个可独立调度的执行单元。每个任务通常包含：任务函数、独立栈、任务控制块（TCB）、优先级和状态。

TCB 保存调度器管理任务所需的信息，典型字段包括：

- `pxTopOfStack`：当前栈顶，任务切换时用于保存和恢复上下文。
- `xStateListItem`：把任务挂入就绪、阻塞、挂起等状态链表。
- `xEventListItem`：把任务挂入队列、信号量等事件等待链表。
- `uxPriority`：当前优先级；启用互斥量时还可能保存基础优先级。
- `pcTaskName`：用于调试和任务统计的名称。
- 栈起始地址、栈深度、通知值等可选信息。

具体字段受 FreeRTOS 版本和配置宏影响，不应依赖 TCB 私有布局编写业务代码。

## 2. 五种常见状态

| 状态 | 含义 | 常见进入方式 |
| --- | --- | --- |
| Running | 正在使用 CPU | 调度器选中 |
| Ready | 可以运行，等待 CPU | 创建任务、解除阻塞 |
| Blocked | 等待时间或事件 | `vTaskDelay`、等待队列/信号量 |
| Suspended | 被显式挂起，不参与调度 | `vTaskSuspend` |
| Deleted | 已删除，资源等待 Idle 任务回收 | `vTaskDelete` |

Blocked 不等于“浪费 CPU 等待”。任务会从就绪链表移出，CPU 可以执行其他任务或进入低功耗。

## 3. 链表在调度中的作用

- 每个优先级通常对应一条就绪链表。
- 延时任务进入延时链表，链表项值常用于保存唤醒 Tick。
- 等待事件时，任务同时借助事件链表项参与按优先级排序的等待队列。
- 链表节点保存所有者指针，调度器可由节点找到对应 TCB。

## 4. 任务函数模板

```c
static void SensorTask(void *argument)
{
    (void)argument;

    for (;;) {
        wait_for_sample();
        process_sample();
    }
}
```

任务通常不应从函数末尾返回；需要结束时调用 `vTaskDelete(NULL)`。

## 5. 工程检查项

- 任务是否可以通过阻塞等待代替轮询？
- 栈深度是否基于高水位线测量，而不是凭感觉设置？
- 任务优先级是否由截止时间和阻塞关系决定？
- 是否存在任务函数意外返回、无限占用 CPU 或无超时等待？
