# 03. 任务通信与同步

## 1. 选型表

| 机制 | 适合场景 | 是否传数据 | 主要特点 |
| --- | --- | --- | --- |
| Queue | 固定大小消息、生产者/消费者 | 是 | 拷贝数据，边界清晰 |
| Binary Semaphore | 事件同步、ISR 唤醒任务 | 否 | 表达一次事件 |
| Counting Semaphore | 资源计数、多次事件累计 | 计数 | 不携带具体数据 |
| Mutex | 保护任务间共享资源 | 否 | 支持优先级继承，不能在 ISR 使用 |
| Event Group | 等待多个布尔条件 | 位标志 | 可等待任意位或全部位 |
| Task Notification | 单接收任务的轻量通知 | 32 位值/计数 | 快、内存开销小 |
| Stream/Message Buffer | 字节流或变长消息 | 是 | 典型场景是单写者单读者 |

## 2. 选择原则

- 需要传递结构体：优先队列。
- ISR 只需唤醒唯一处理任务：优先任务通知或二值信号量。
- 保护 UART 打印、I²C 总线等任务共享资源：互斥量。
- 等待“网络就绪且配置完成”：事件组。
- 连续字节流：Stream Buffer 或自建环形缓冲区。

## 3. 队列传指针的风险

队列默认复制元素内容。如果队列元素是指针，只复制指针值，必须明确：

- 指向对象在消费完成前仍然有效。
- 谁负责释放或归还缓冲区。
- 多个消费者是否可能同时修改。

资源受限系统可使用固定缓冲池加所有权转移，避免频繁动态分配。

## 4. 优先级反转

低优先级任务持有锁，高优先级任务等待锁，中优先级任务不断抢占低优先级任务，就会延长高优先级任务等待时间。互斥量的优先级继承可以缓解这一问题，但仍应缩短持锁区间。

## 5. 超时是接口的一部分

永久等待应是有意识的设计。对外设、通信和共享资源，建议使用有限超时，并记录：

- 超时次数。
- 队列峰值和发送失败次数。
- 最长持锁时间。
- 恢复动作是否成功。
